# Agent Contract Testing / Agentic E2E: Does It Survive Scrutiny?

**Short answer: no, not as written.** A broad "Agentic E2E platform" that tests JEV, Browser Use, Stagehand, Skyvern and computer-use agents across correctness, security, cost and regression is a crowded, platform-exposed product with weak evidence of willingness to pay among app developers. One narrow version does survive: an open-source **outcome and side-effect verifier**. It answers "did the backend state actually change correctly, and did nothing forbidden happen?" when a browser agent claims it is done, and it runs as a CI gate. That version is worth a cheap 3–4 week validation experiment, not a 6-month commitment.

## TL;DR

- **The pain is real; the market for app developers is not yet proven.** Agents falsely claiming success are well documented. In Browser Use issue #5955, a structured `done` schema defaulted incomplete tasks to success, giving "3/3 false success" when records were blocked by HTTP 403. Prompt injection is also measured: Anthropic's August 2025 Claude for Chrome red-team found that 29 of 123 test cases succeeded (23.6%) without mitigations. But the money in "testing agents" has gone to two places. One is RL environment and eval vendors selling to frontier labs (HUD, Halluminate, Plato). The other is AI QA tools that test *ordinary apps* (Momentic's $15M Series A on Nov 24, 2025, led by Standard Capital; Playwright Test Agents). Very little has gone to tools that test browser agents built by app teams.
- **Platform absorption risk is high for the generic layers.** OpenAI bought Promptfoo (March 9, 2026) for agent red-teaming inside Frontier. Microsoft ships PyRIT-based agent red-teaming in Foundry. Playwright ships trace, MCP and agentic test tooling. Browser Use, Browserbase and Laminar already ship replay, observability and benchmarks. The parts hardest to commoditize are **application-specific backend-state assertions, forbidden side-effect contracts, and a framework-neutral contract format**.
- **Verdict: BUILD ONLY AS A SMALL VALIDATION EXPERIMENT.** Build a small OSS tool (`agent-contracts`: YAML contract → run agent → assert DB/API state and forbidden actions → JUnit/HTML evidence). Use it to recruit 10–15 teams that ship browser agents. Kill it unless at least 5 teams run it on real workflows and at least 2 agree to a paid pilot or design-partner commitment. Rudra's red-teaming and trajectory-review background makes the security and side-effect angle his comparative advantage. JEV itself is a two-week-old novelty, not a foundation.

## Executive conclusion

1. **The problem exists and is specific.** Browser agents misreport completion, take unrequested actions and remain injectable:
   - In Browser Use issue #1763, the agent logged "Task complete: Email sent" when, per the reporter, "the task was not completed and the email was not sent."
   - In issue #56, an agent asked only to navigate to GitHub tried to sign up with "you@example.com" and fake passwords.
   - AMD's GAIA agent (issues #3750, #3943) ended loops with "Task completed… No further action needed" when nothing was done.
   - These are repeated, independent reports across projects. **STRONG SIGNAL.**

2. **The most-funded slice of "agent testing" sells to model labs, not app teams.**
   - HUD's own announcement (June 2026) reports "$16M in total funding," led by Standard Capital, and says "Over 50 businesses use HUD." The company describes working "with frontier labs to evaluate Computer Use Agents."
   - Halluminate counts "four leading US AI labs" among its customers.
   - Plato builds replica-site environments.
   - This is a data/RL business needing enterprise sales and lab relationships, not a solo CLI. **STRONG SIGNAL.**

3. **The closest analogy, voice-agent testing, shows that "testing agents" can become a funded category once agents are deployed at scale.**
   - Coval raised a $28M Series A in June 2026 led by Norwest, with Base10 Partners, Twilio Ventures and Y Combinator. That brings its total funding to $31M (TechFundingNews), and it reports "over 60 organizations" as users, including Zoom and Deepgram.
   - Hamming raised $4.3M and Cekura $2.4M; Cekura sells a $30/month developer tier.
   - Browser agents do not yet have voice agents' production deployment density (call centers with per-call economics). **INFERENCE.**

4. **JEV is hype-driven, not a stable base.**
   - `browser-use/jev-ultrafast` was created September 16, 2026, one day after TypeSafe launched its closed, early-access Jev decision model.
   - It reached about 21.6k stars in 15 days, but a GitHub-trend tracker classified it as "Cooling," with the two-day pace at 7% of the previous week and a half.
   - Its own README lists no shadow DOM, frames, canvas or upload support.
   - Building an adapter-first product around JEV ties you to a waitlisted proprietary API. **VERIFIED (dates/stars from tracker), INFERENCE (implication).**

5. **Incumbents are converging on the generic layers.**
   - Playwright 1.56 (October 2025) shipped Planner/Generator/Healer agents; 1.59 added CLI trace analysis.
   - OpenAI owns Promptfoo. Microsoft integrates PyRIT into Foundry.
   - Laminar ($3M seed, March 2026) is Browser Use's default observability layer, with browser session replay and a debugger that restores DOM state.
   - Trace, replay, red-team prompt packs, model comparison and LLM-judge scoring are commoditizing now. **VERIFIED.**

6. **What is weakly served:**
   - backend-truth verification (did the order, CRM record or refund actually change correctly);
   - forbidden side-effect detection at the network/DB layer rather than in LLM text;
   - statistically sound pass/fail for non-deterministic agents in CI;
   - a framework-neutral contract format.
   - The Cloud Security Alliance's evaluation of PyRIT says it "tests LLM responses, not internal agent state" and cannot natively observe whether an agent "actually executes unauthorized tools." That gap is real. **STRONG SIGNAL.**

7. **Willingness to pay from app teams for *this exact* product is UNKNOWN.** I found no case study, procurement page or job posting showing a company buying "browser-agent contract testing" as such. Adjacent spend exists:
   - Browserbase reports 1,000+ customers.
   - Momentic reports "more than 2,600 users at organizations including Notion, Xero, Bilt, Webflow, and Retool" (The AI Insider).
   - Coverage of the March 9, 2026 OpenAI acquisition reported Promptfoo in "more than 25% of Fortune 500 companies" with 350,000 developers (WinBuzzer).

   Adjacent spend is not evidence for this product.

8. **For Rudra specifically, the comparative advantage is security and trajectory verification, not browser infrastructure.** His red-teaming, trajectory review, provenance benchmark ("who-said-that") and agent-containment writing map directly onto "prove the agent did not do anything forbidden." Generic E2E maps onto nothing he uniquely owns.

9. **Decision:** run a 3–4 week, budget-capped validation of the narrow verifier. If it passes, continue as OSS + paid pilots. If it fails, fold the artifacts into the article series and a public benchmark (reputation value preserved) and move on.

**Final verdict: BUILD ONLY AS A SMALL VALIDATION EXPERIMENT.**

## 1. What the product actually is

The label "Agentic E2E" hides three different products:

| Job | What it really is | Who already does it |
|---|---|---|
| Test *ordinary web apps using agents* | AI QA | Momentic, Playwright Test Agents, QA Wolf, mabl, testRigor, Shiplight, TestMu (ex-LambdaTest) |
| Test *agents themselves* (are they capable?) | Benchmark / RL environments | HUD, Halluminate, Plato, WebArena/BrowserGym, Browser Use benchmark, Stagehand evals |
| Test *a specific deployed agent against a specific app* (did it do the right thing, and only that?) | Agent contract / outcome verification | Mostly ad hoc; partially Laminar evals, EvalView, agentrial, Promptfoo, Foundry |

The original proposal is the third row. Its defensible core is **verification of outcomes and side effects against ground truth the agent cannot see or fake**: database rows, API responses, network calls, permission boundaries. Its weakest parts are the ones that look most impressive in a demo: cross-framework adapters, trace replay, and model leaderboards.

## 2. Problem evidence

| Pain | Evidence | Strength |
|---|---|---|
| Hallucinated completion | Browser Use #5955 / PR #5946: structured `done` "hides success, while parsing defaults it to True"; 3/3 false successes when blocked by HTTP 403. #1763: claimed "Email sent," not sent. AMD GAIA #3750/#3943: "Task completed" after a loop-guard stop. | STRONG SIGNAL (multiple independent repos) |
| Unrequested / unauthorized actions | Browser Use #56: agent signed up and tried password resets with fake credentials when asked only to navigate | VERIFIED (single, older issue) |
| Prompt injection | Anthropic Claude for Chrome pilot: 123 test cases, 29 scenarios, 23.6% ASR without mitigations → 11.2% with them; challenge set 35.7% → 0%. WASP (Meta, arXiv 2504.18575): agents "begin executing the adversarial instruction between 16 and 86% of the time but only achieve the goal between 0 and 17%." "ShadowPrompt" zero-click injection disclosed and patched in Claude's extension (early 2026, secondary reporting). | STRONG SIGNAL |
| Injection rates falling at the model layer | Anthropic GA post: earlier evaluation "saturated" at 0%; 0.3% ASR against Fable 5 on newer tests; help center claims "less than 0.08%" in internal testing | VERIFIED (vendor-reported, not independent) |
| Real-web brittleness | Halluminate/Skyvern WebBench: 2,454 open tasks across 452 sites; agents "still struggle heavily with NON-READ tasks"; best (Anthropic CUA) about 66% | VERIFIED (vendor benchmark) |
| Non-determinism makes CI hard | AgentAssay (arXiv 2603.02601, March 2026): "No test caught the regression… the daily reality"; 50 scenarios × 100 trials = 5,000 invocations per regression check | VERIFIED (paper) |
| Reproducibility / debugging | Laminar's pitch: failures "15 minutes into a run" force full restarts; it built DOM-state-restoring replay | VERIFIED (vendor) |
| Cost/latency unpredictability | JEV exists precisely because per-step LLM calls are slow and expensive (claimed 1,092 → 101 browser protocol calls) | VERIFIED (vendor claim) |

Count: more than 8 independent primary sources on false completion, injection and non-determinism. I did **not** find repeated evidence of teams paying consultants or allocating headcount specifically to browser-agent testing. **UNKNOWN.**

An important counter-signal: model vendors are rapidly driving their own injection rates toward zero on their own evals. The "security" pitch therefore weakens over 6–12 months for frontier-model agents. It stays strong for app-specific policies (e.g., "never touch a customer record outside this tenant") that no model vendor can know.

## 19. MVP specification

- **Exact product:** An open-source CLI and GitHub Action that runs a browser agent against a staging app and passes or fails it on backend ground truth and forbidden side effects, not on the agent's own claim.

- **Exact pain:** The agent says "done" when the record was not created, was created wrong, or something else was touched, and nobody finds out until a customer does.

Continue only if at least 2 paid pilots or commitments **and** at least 3 weekly active teams. In that case, budget 8 more weeks for the hosted evidence layer.

# The most interesting issue is actually #132

This one is easy to miss.

JEV uses positional action IDs like:

```text
[e1] Add
[e2] View
[e3] Delete
```

Then the page changes.

An old `e2` can potentially resolve to a **different live element** and still pass the freshness check. The issue shows that the action's stable node identity exists internally, but the execution path does not verify that the selected node is the same node that existed when the decision was made. That's a **very serious class of problem**.

Because it isn't:

> “agent failed.”

It is:

> **agent performed a different action than the one it intended.**

That is much closer to a security/safety primitive.

 ↓
permissioned credentials
 ↓

auto-destroy

For developers running agents locally, this is potentially much more valuable than another browser agent.

# The most interesting issue is actually #132

This one is easy to miss.

JEV uses positional action IDs like:

```text
[e1] Add
[e2] View
[e3] Delete
```

Then the page changes.

An old `e2` can potentially resolve to a **different live element** and still pass the freshness check. The issue shows that the action's stable node identity exists internally, but the execution path does not verify that the selected node is the same node that existed when the decision was made. [GitHub](https://github.com/browser-use/jev-ultrafast/issues/132?utm_source=chatgpt.com)

That's a **very serious class of problem**.

Because it isn't:

> “agent failed.”

It is:

> **agent performed a different action than the one it intended.**

That is much closer to a security/safety primitive.

---

# This suggests a better product than “Agent Testing”

## Agent Action Integrity

The product sits between:

```text
Agent
   ↓
proposed action
   ↓
YOUR SAFETY LAYER
   ↓
Browser
```

It checks:

```text
Was this the same element?
Is it still visible?
Did its label change?
Did its role change?
Did its surrounding context change?
Is it allowed?
Is it destructive?
Is confidence sufficient?
```

Then:

```text
ALLOW
DENY
REPLAN
ASK HUMAN
```

That is much more concrete than generic evaluation.

And the need is directly evidenced by JEV's own issues. [GitHub](https://github.com/browser-use/jev-ultrafast/issues/132?utm_source=chatgpt.com)

# Issue #120 makes this even more interesting

The confidence issue explicitly says JEV records confidence/target-confidence, but ordinary actions are still executed directly, without the same explicit uncertainty boundary used for terminal decisions. The reporter's experiment also found that adding untrusted-page instructions changed probabilities without changing the chosen candidate. [GitHub](https://github.com/browser-use/jev-ultrafast/issues/120?utm_source=chatgpt.com)

That suggests a primitive:

```text
agent confidence
      +
target freshness
      +
page context
      +
policy
      ↓
action risk score
```

Example:

```text
CLICK "Delete customer"

confidence             0.82
target freshness       PASS
page context           changed
action risk             CRITICAL

→ REQUIRE APPROVAL
```

That is an actual runtime feature.

# Issue #149 points to a different opportunity

The semantic-state issue is excellent.

Currently JEV flattens visible text:

```text
MacBook Air
$999
In stock
ThinkPad
$1299
[7] Add
[8] Add
```

The proposal is to preserve compact relationships:

```text
Product Card
 ├── MacBook Air
 ├── $999
 ├── In stock
 └── ActionRef [7]

Product Card
 ├── ThinkPad
 ├── $1299
 └── ActionRef [8]
``` :chatgpt-content-reference{index="4"}


This is potentially **more interesting technically than building a browser agent.**

You could build:

# Semantic Web State Compiler

```text
DOM
 ↓
visible/interactive extraction
 ↓
semantic normalization
 ↓
compact agent representation
 ↓
LLM / Jev / any decision model
```

So agents consume:

> **meaningful UI state**

rather than raw DOM or screenshots.

Potentially:

```text
JEV
Browser Use
Claude
GPT
Gemini
OpenAI CUA
```

all consume the same normalized representation.

That is a much deeper infrastructure idea.

But again: **don't assume it is monetizable**. We'd need to research competitors such as accessibility-tree frameworks, Stagehand, Playwright, Browser Use, WebMCP and semantic DOM projects before committing.

# Issue #23 reveals another hidden problem

JEV's element table only captures native controls and selected ARIA roles.

Modern sites often make clickable items out of:

```html
<div>
<li>
<span>
```

with JavaScript click handlers.

Those aren't exposed, so the agent can't click them at all. The reported result is repeatedly typing/retrying until the action budget is exhausted. [GitHub](https://github.com/browser-use/jev-ultrafast/issues/23?utm_source=chatgpt.com)

That means:

> **“What can the agent legally interact with?”**

is itself a major abstraction.

A potential product:

# Universal Action Graph

Instead of:

```text
DOM → elements
```

build:

```text
DOM + accessibility + event listeners + visual cues
                        ↓
                 Action Graph
```

Each candidate:

```text
Node ID
Role
Label
Context
Coordinates
Event handler
State
Freshness
Confidence
```

Then browser agents consume the graph.

This is technically compelling.

# Issue #100 is a cost problem

The post-action observation can fail, leaving `page_changed = null`; that interferes with the no-progress detection and causes the agent to keep spending model calls on a stalled run. [GitHub](https://github.com/browser-use/jev-ultrafast/issues/94?utm_source=chatgpt.com)

That suggests:

# Agent Recovery Engine

```text
Observation failed
      ↓
Classify failure
      ↓
Retry observation
      ↓
Re-observe
      ↓
Check progress
      ↓
Re-plan
```

rather than:

```text
error → another LLM call → another LLM call → burn money
```

And this has a direct commercial metric:

> **cost wasted on failed agent runs.**

That is much easier to sell than “AI reliability.”
